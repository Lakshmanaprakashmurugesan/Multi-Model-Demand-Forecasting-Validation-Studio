# Execution Evidence Guide

The repository preserves `app.py` byte-for-byte from the supplied source. Runtime evidence is generated by sidecar tools and stored separately.

## 1. Static/source-integrity validation

```bash
python run_validation.py
```

Outputs are written to `evidence/execution/`.

## 2. Model execution without editing app.py

The sidecar runner parses the exact function definitions from `app.py` and executes them while omitting Streamlit-only page rendering statements.

```bash
python tools/model_execution_runner.py --models all --output-dir evidence/model_runs/full_run
```

This produces, when dependencies are available:

- `model_leaderboard.csv`
- per-model validation predictions
- per-model future forecasts
- `combined_future_forecast.csv`
- `forecasting_intelligence_results.xlsx`
- `execution_status.csv`
- `run_manifest.json`
- `VALIDATION_REPORT.md`

## 3. Streamlit UI execution

```bash
streamlit run app.py
```

Use the built-in demo or your permissible synthetic/public data and retain screenshots under `screenshots/`.

## Evidence boundaries

Execution evidence demonstrates that the repository runs under the recorded environment and produces the retained outputs. It does not by itself prove historical employer results, production deployment, third-party adoption, government endorsement, or national-scale outcomes.
